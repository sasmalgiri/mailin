## 2. Paths read and found without a product cap

- **Import:** mbox / eml (offset engine and streaming fallback), PST / OST (MS-PST reader, batches), NSF
  (batches), MSG, EMLX, Apple Mail packages and library, Maildir, EML folders, ZIP, gzip, tar, OLM. The
  only ceilings are the format's own (ANSI PST 2 GB; NSF warnings), the device's (exFAT 4 GiB per file,
  free scratch space + 64 MiB margin) and the single-message threshold above, each stated. **Correction (audit A11, same day):** the 4 GiB per-file ceiling is FAT32's, not exFAT's; the location check now reads the file-system type from the mount table and warns about exFAT only for its missing journal.
- **Indexing:** chunk index (48 K-character chunks, no cutoff), attachment documents (whole text; Office
  part budget stated; OCR scales images, reads every one), speech (per file, 20-minute wait stated in
  the state).
- **Query:** `SearchSpecCompiler` compiles one statement with bound values over the whole index; counts
  come from SQL; the "may still match" count is shown rather than dropped.
- **Paging:** keyset / ranked cursors; the list window keeps 500 rows in memory and asks for more — a
  memory budget, not a result cap, and the total count is shown.
- **Export:** every format streams its selection (`runStreamingExport`); the selection is frozen at
  start (`snapshotMaxRowID`); the inventory lists every message and the receipt reconciles counts.

> available storage, memory and the supported archive format. See the tested-workload matrix for the

Tested workloads: `SCALE_RESULTS.md` (100 MB synthetic mbox / PST / EML folder / MSG rows of

from "Archives of any size" to the wording above.

## 4a. Addendum after the external audit of b4b502f (same day)

The owner's implementation audit found windows this record had missed, all fixed the same day:

| Finding | Was | Now |
|---|---|---|
| A02 | "All words" matched only when every word sat in one 48 K-character chunk — a silent cap on long texts | Every word somewhere in the same text (per-word intersection); phrases up to a chunk verified on the exact text across adjacent chunks; only a phrase longer than a whole chunk falls back to all-words, and the summary says so |
| A04 | Children of a ZIP that nothing could read were dropped as "no text"; one level only; tar/gzip attachments unopened | Every child accounted for or listed; three levels; tar/tgz/gz opened; 1 GiB extracted-bytes budget per attachment, named when it bites |
| A03 | Legacy Excel read strings only, yet "complete" | Every cell kind with its address; numbers stated as stored |
| A06 | An OCR failure read as "no text" | Per-page outcome; failures named; partial / failed states |
| A11 | 4 GiB ceiling attributed to exFAT | FAT32's; exFAT warned about its missing journal instead |

Still stated, not removed (audit A10): the 100 MiB single-message text threshold, the 64 MiB part/member
guard, three archive levels and the 1 GiB archive budget. Replacing them is streaming/resumable extraction
work, not a deleted guard — tracked as the open design item in `FIVE_JOBS_TRACKER.md`.
